# Gaze + Jev — CPU 최소 구현

웹캠 → **UniGaze-B** → 9점 왕복 보정 → 주변 DOM 요소 → 가장 가까운 요소 선택(NearestSelector, Jev는 선택) → 입 벌렸다 다물기로 클릭.

Windows 또는 Linux + Chrome, 단일 모니터에서 사용하는 개인·연구용 시제품입니다. 시선 모델은 [UniGaze-B](https://github.com/ut-vision/UniGaze)(ViT-B/16, 약 8600만 개 파라미터, `unigaze_b16_joint` 가중치)입니다. 설치할 때 공식 가중치를 받아 ONNX로 바꾸고, 실행 중에는 **ONNX Runtime으로 CPU에서만** 돌립니다. CUDA를 설치하거나 사용하지 않습니다. (이전 모델 GazeTR-Hybrid는 git 기록에 남아 있습니다.)

## 실행

1. 프로젝트 폴더를 `C:\eye_cur`처럼 **영어로만 된 경로**에 둡니다. 한글 폴더·한글 사용자 이름·OneDrive `바탕 화면` 아래에서는 MediaPipe가 모델 파일을 열지 못합니다. 그 폴더에서 일반 PowerShell 창(ISE·우클릭 실행 아님)을 열고 `powershell -ExecutionPolicy Bypass -File .\setup.ps1`을 실행합니다. 마지막의 모델 로딩 점검(`PASS`)까지 나와야 설치 완료입니다. `DLL load failed`가 나오면 [VC++ 재배포 패키지](https://aka.ms/vs/17/release/vc_redist.x64.exe)를 설치합니다. 점검은 기본인 8비트(int8) 모델로 속도를 잽니다. `Server threads`로 실제 쓸 스레드 수가, 그 줄 위에 그 스레드 수의 시간이 나옵니다. 시간이 충분히 짧고(약 50ms 이하) 정확도를 조금 더 원하면 `.env`에 `GAZE_INT8=0`을 넣어 원래 크기(fp32) 모델을 씁니다(아래 "시선 모델 속도" 참고). 폴더를 옮겼다면 setup을 다시 실행합니다. 이미 설치를 완료했다면 생략합니다.
2. (선택, USE_JEV) 기본값은 API 키 없이 동작합니다. Jev를 쓰려면 `extension/content.js`의 `USE_JEV`를 `true`로 바꾸고 `.env`의 `TYPESAFE_API_KEY=` 뒤에 [TypeSafe 콘솔](https://console.typesafe.ai/)에서 발급한 키를 넣습니다. 키는 확장에 입력하지 않습니다.
3. `powershell -ExecutionPolicy Bypass -File .\start.ps1` 실행. 콘솔에 표시되는 **연결 토큰**을 복사합니다(`runtime.json`에도 있습니다). Windows 10 콘솔에서 글자를 마우스로 선택한 채 두면 서버가 멈추므로, 복사 후 `Esc`를 누릅니다.
4. Chrome에서 `chrome://extensions` → 개발자 모드 → **압축해제된 확장 프로그램을 로드합니다** → 이 프로젝트의 `extension` 폴더 선택.
5. `http://127.0.0.1:8765/demo`에 접속합니다. 확장 아이콘 → 연결 토큰 입력 → **시작**. 저장된 보정이 있으면 바로 이어서 쓰고, 다시 하려면 확장 아이콘의 **다시 보정**을 누릅니다. 팝업에는 실행 상태, 마지막 보정의 점 오차, **다시 보정**·**중지** 버튼, **화면에 정보 표시** 스위치가 있습니다.
6. 머리·창 위치를 고정하고, 밝은 화면에 나타나는 점을 바라봅니다. 보정을 누르자마자 점을 보기는 어려워서, 첫 점(왼쪽 위)을 보여 준 채 2초를 센 뒤 시작합니다. 시선 값이 오기 전에는 보정 화면에 무엇을 기다리는지(얼굴을 찾는 중, 눈 뜬 상태를 배우는 중 등) 표시합니다. 3×3 점(가장자리 10%)을 ㄹ자로 한 번, 거꾸로 한 번 봅니다(18번, 약 29초). 다음 점 자리는 회색 점선 원으로 미리 보입니다. 점은 크게 나타났다가 0.8초 동안 작아지는데(transform 애니메이션은 Hyprland·화면 배율 1.2에서 시작 직후 화면이 깜빡이고 찢어져서, 점의 크기를 바꾸는 전환으로 만듭니다), 이때는 눈이 옮겨 가는 중이라 표본을 버리고, 작아진 뒤 0.8초 동안 모읍니다. 0.8초를 기다리는 이유는 눈꺼풀이 눈보다 늦게 내려오기 때문입니다. 보정 기록 2개에서 아래쪽 점은 0.5초 뒤에도 시선 값이 계속 바뀌었고, 0.8~1초 뒤 값만 쓰면 아래 줄 오차가 줄었습니다(88→57px, 106→80px). 눈을 감아 표본이 3개보다 적으면 최대 2.1초까지 기다리므로 2초 세기를 더해도 전체가 40초를 넘지 않습니다(2 + 18 × 2.1 = 39.8초).
7. 버튼을 바라봅니다. 초록 테두리가 원하는 요소에 생기면 **입을 0.5~2.0초 벌렸다 다뭅니다**. 다물 때 한 번 클릭합니다. 입을 벌리는 동안 테두리가 주황색으로 바뀌어 클릭이 진행 중임을 알려 줍니다. 정보 표시를 켜면 나오는 패널의 `MAR` 값으로 문턱값(`backend/gestures.py` 위쪽, 벌림 0.20 / 다뭄 0.12. 처음 0.30 / 0.20은 입을 꽤 크게 벌려야 해서 낮췄습니다)을 맞춥니다. 기존 양눈 감기(0.6~2.0초) 클릭은 `extension/content.js`의 `CLICK_MODE`를 `'eyes'`로 바꾸면 씁니다. 확장 아이콘의 **중지**로 종료합니다.
8. 사이트를 방해하지 않도록 화면에는 기본으로 빨간 원본 점(필터 전 시선), 파란 커서(필터 후), 초록 테두리만 보입니다. 확장 아이콘의 **화면에 정보 표시**를 켜면 왼쪽 아래 정보 상자(눈·입 상태, 머리 기울기, 떨림, 상태 문구)가 보이고, 단축키 `F`(떨림 필터 바꾸기)와 `ESC`(중지)가 동작합니다. 꺼 두면 사이트의 `F`·`ESC` 키를 가로채지 않습니다. 정보 상자는 마우스가 통과하므로 아래 사이트를 그대로 누를 수 있습니다.

### Linux (Arch 등)

Arch 기본 Python 3.13에는 `mediapipe 0.10.21` 휠이 없어 `setup.sh`가 uv로 Python 3.11 가상환경(`.venv/bin/python`)을 따로 만듭니다. `uv`가 필요합니다(`sudo pacman -S uv`).

```bash
./setup.sh                              # 1번 대신 (CPU torch 2.7.1 + requirements.txt, UniGaze 받아 ONNX로 변환)
.venv/bin/python scripts/check_camera.py  # 카메라·얼굴·시선 출력 확인
./start.sh                              # 3번 대신
```

카메라는 Windows에서 DirectShow, Linux에서 V4L2로 엽니다. 나머지 4~7번은 같습니다.

PowerShell 실행 정책 때문에 스크립트를 열 수 없다면 해당 실행에만 `powershell -ExecutionPolicy Bypass -File .\start.ps1`을 사용합니다.

보정 완료 후 다른 일반 웹사이트 탭으로 전환하거나 페이지를 이동해도 자동으로 이어집니다. 보정값은 확장 저장소(`chrome.storage.local`)에 저장되어 중지하거나 브라우저를 다시 켜도 이어집니다. 창 크기·위치·화면 배율이 바뀌면 저장된 보정을 지우고 새 좌표에 맞춰 다시 보정합니다. Chrome 설정·새 탭 등 제어 불가 페이지와 다른 앱에서는 입력을 일시 중지하며(다른 앱으로 가도 페이지와의 연결은 끊지 않고, 페이지가 화면에 보이지 않으면(다른 탭·최소화) 페이지가 스스로 멈춥니다. 키보드 초점은 따지지 않습니다. Linux(Wayland)에서는 확장 팝업만 열어도 창이 초점을 잃었다는 이벤트가 오고, 돌아온 뒤에도 페이지가 초점이 없다고 나오는 경우가 있어서 "다른 앱 사용 중"에 멈추거나 보정 표본이 버려졌습니다. 그래서 Chrome이 화면에 보이기만 하면 다른 앱에 키보드 초점이 있어도 시선 커서와 입 클릭이 동작합니다. 쓰지 않을 때는 팝업의 **중지**를 누릅니다), 일반 웹페이지로 돌아오면 자동으로 계속합니다. ESC와 중지 버튼은 실행 세션 전체를 종료합니다.

## 동작과 제한

- Python 앱이 웹캠·얼굴 랜드마크·UniGaze를 처리합니다. PyTorch(CPU 휠)는 설치 때 UniGaze를 ONNX로 바꾸는 데만 쓰고, 서버는 ONNX Runtime만 씁니다. `vendor/unigaze.py`는 공식 코드(timm 0.3.2 필요, 지금 torch와 맞지 않음)와 같은 계산을 torch만으로 다시 적은 것이며, 공식 코드와 출력 차이가 3×10⁻⁷ 이하인지 확인했습니다.
- 시선 모델 속도(Ryzen 7 5825U, 얼굴 한 장): 이전 GazeTR 27ms · UniGaze torch 170ms · ONNX Runtime fp32 104ms · **ONNX Runtime int8 57ms(기본)**(스레드 4개). int8은 출력이 fp32와 최대 0.035rad(약 2°) 다르고, 같은 얼굴에 카메라 잡음만 넣었을 때 흔들림이 20~50% 커집니다. 하지만 실제로 써 보니 흔들림이 크지 않고 속도가 더 중요해서 int8을 기본으로 합니다. 보정은 int8 출력으로 하므로 고정된 차이는 보정이 흡수합니다. fp32를 쓰려면 `.env`에 `GAZE_INT8=0`. fp16은 일반 CPU에 전용 계산기가 없어 빨라지지 않아 쓰지 않았습니다. 카메라는 초당 30장이지만 추론은 이전 추론이 끝나야 다음 장을 받으므로 저절로 2~3장마다 한 번 추론하고, 그 사이는 확장의 응시 고정 필터가 메웁니다.
- ETH-XGaze 공식 3D 얼굴 템플릿의 눈꼬리 4점과 코 양옆 2점을 사용해 얼굴 영상을 224×224로 정규화합니다. 눈 중심과 코 중심을 동일한 비중으로 사용합니다. UniGaze 공식 코드에 맞춰 정규화 얼굴(초점 960, 거리 600, 224×224)을 **RGB로 바꾸고 0~1로 나눈 뒤 ImageNet 평균·표준편차로 정규화**합니다(`backend/tracker.py`의 `face_tensor`). UniGaze 출력은 [pitch(위아래), yaw(좌우)] 순서라서, 예전처럼 [좌우, 위아래]로 바꿔 확장에 보냅니다. 같은 얼굴을 좌우로 뒤집어 넣으면 yaw만 부호가 바뀌는 것으로 순서를 확인했습니다.
- 카메라는 별도 스레드에서 계속 읽고 추론에는 최신 프레임만 사용합니다. 보정 점이 바뀌기 전에 촬영한 프레임, 깜빡임 직후 표본, 일시적인 이상치를 제외합니다. 보정 통과 기준을 낮추지는 않았습니다.
- 기본 카메라 내부 파라미터는 추정값입니다. 화면 보정은 시선→화면 좌표를 맞추는 과정이며 정밀 카메라 보정을 대신하지 않습니다. 정확도는 실제 사용자·카메라에서 확인해야 합니다. `CAMERA_INTRINSICS`에 `camera_matrix`와 `dist_coefficients`가 있는 JSON 경로를 지정할 수 있습니다.
- MediaPipe 홍채 점(`refine_landmarks=True`)으로 눈 구석 사이 홍채 위치(눈 너비 단위)를 함께 기록하지만, 회귀 입력은 시선 각도 2개뿐입니다. 예전 GazeTR 보정 기록 4개에서 응시 점(모서리 정지 + 검증 점)만으로 점 하나씩 빼고 맞혀 보니, 2개 입력이 4개 입력(홍채 포함)보다 모두 정확했습니다(85/117/86/65px vs 113/174/101/74px). 점이 9개뿐이면 입력이 많을수록 잡음까지 외웁니다.
- 패널에 머리 기울기(두 눈을 잇는 선의 각도)와 카메라까지 거리를 표시하고, 보정 후에는 보정할 때와의 차이(°, %)도 보여 줍니다. 얼굴 정규화는 이 둘의 변화를 시선 값에서 지우지 못하므로, 이 차이가 클 때 가장자리 오차가 커지는지 확인하는 측정용입니다. 거리는 카메라 초점거리를 추정해 계산하므로 절대값보다 변화율을 봅니다.
- 눈 크기 경고: 보정 중 눈 열림 범위(5~95%)를 0.05 넘게 벗어나면 패널에 "눈을 보정 때보다 크게/작게 떴어요"를 노란 글씨로 표시합니다. 눈꺼풀이 내려오면 시선 모델·홍채 값이 아래를 보는 것처럼 바뀌기 때문입니다. (눈 뜬 정도를 계산으로 빼는 보정도 시도했지만, 눈을 크게/가늘게 뜨는 동안 시선도 같이 흔들려 기울기가 부정확했고 실제로 더 나빠져서 뺐습니다.)
- 예전 움직이는 점 보정을 바꾼 이유(기록 4개 분석): ① 보정 직후 고정 점 4개를 볼 때 예측이 한쪽으로 몰려 빗나갔습니다(예: 한 기록에서 4점 모두 왼쪽 위로 65~150px). 따라보는 눈은 점보다 늦고 덜 움직여서, 버튼을 응시할 때와 값이 다릅니다. ② 시선 지연 추정이 4번 중 3번 상한(300ms)에 걸려 점과 시선을 짝짓는 것부터 틀렸습니다. ③ 어두운 남색 화면에서 보정하고 밝은 웹페이지에서 썼습니다. 화면 밝기가 바뀌면 얼굴 조명과 동공 크기가 바뀌어 시선 값이 통째로 밀릴 수 있습니다. 그래서 지금은 웹페이지처럼 밝은 화면에서 고정 점을 응시하게 합니다.
- 왕복 순서: 점마다 앞 바퀴와 뒤 바퀴 차례의 평균이 같아서(8.5번째), 시간이 지나며 천천히 밀리는 시선 값(드리프트)이 모든 점에 똑같이 더해집니다. 똑같이 더해진 값은 회귀의 상수항이 흡수하므로 점 사이 관계가 틀어지지 않습니다. 점마다 바퀴별 중앙값을 구하고 두 바퀴를 평균해 표본 9개로 회귀합니다.
- 보정 표본(시선 값·촬영 시각·점 번호·차례·머리 기울기/거리/끄덕임/돌림·홍채 위치)과 점별 중앙값을 서버가 `logs/pursuit.jsonl`에 한 줄씩 저장합니다. 카메라 이미지는 저장하지 않습니다. 회귀나 입력을 바꿨을 때 같은 자료로 오차를 비교하는 데 씁니다.
- 사용 중 드리프트 보정(클릭 보정, 기본 꺼짐: `extension/content.js`의 `CLICK_DRIFT = true`로 켬): 입 벌리기로 클릭하면 그 요소를 보고 있었다고 보고, 대상이 고정되기 직전 0.5초의 예측 위치와 요소 가운데의 차이를 절반만큼 오프셋에 더합니다. 200px보다 긴 방향(긴 링크의 가로 등)은 어디를 봤는지 알 수 없어 고치지 않습니다. 고친 값은 패널에 "클릭 보정 (x, y)px"로 보이고 저장되며, 다시 보정하면 0으로 돌아갑니다.
- 표본 9개로 1차 회귀를 합니다(2차는 계수가 많아 9개로는 과적합). 별도 검증 점 대신, 점 하나씩 빼고 회귀한 뒤 뺀 점을 예측하는 교차검증 오차를 "점 오차"로 픽셀 단위로 표시합니다. 확장 아이콘의 **다시 보정** 버튼으로 재측정할 수 있습니다. 예전 움직이는 점 방식이나 GazeTR로 저장된 보정은 이어 쓰지 않고 새로 보정합니다.
- 검색 결과 같은 제목 링크는 제목의 실제 텍스트 영역을 후보로 삼고 해당 제목의 상위 링크를 클릭합니다. 여러 줄 링크, 바깥 영역 높이가 0인 링크, 중첩된 클릭 역할을 처리합니다. 가려진 링크와 클릭 직전 목적지가 바뀐 링크는 제외합니다.
- 여러 사이트에서 자동으로 이어지기 위해 HTTP/HTTPS 사이트 접근 권한을 사용합니다. DOM 수집과 클릭은 현재 보고 있는 탭에만 적용하며, 이전 탭에서 늦게 도착한 Jev 응답은 버립니다. 보정 도중 탭을 바꾸면 미완료 보정은 새 탭에서 다시 시작합니다.
- 기본(`USE_JEV = false`): 시선 주변 후보 중 가장 가까운 요소가 0.3초 이상 계속 1등이면 선택하고, 이미 선택이 있으면 새 1등이 30px 이상 더 가까울 때만 바꿉니다. 숫자는 `extension/core.js` 위쪽 상수입니다. 서버로 아무것도 보내지 않으므로 API 키와 비용이 필요 없습니다.
- `USE_JEV = true`일 때: 시선 주변의 보이고 활성화된 요소 최대 8개를 Jev `choice` 질문에 넣습니다. 선택 불가를 뜻하는 `none`을 포함합니다. 호출은 최대 초당 2.5회이며 연속 사용 시 API 비용이 발생합니다.
- Jev에는 후보의 이름·역할·사각형·거리와 최근 시선 좌표만 전송합니다. 영상, 입력 필드 값, 페이지 전체 HTML, API 키는 전송 자료에 포함하지 않습니다. 단, 버튼 등의 공개 텍스트 자체가 민감한 페이지에서는 그 텍스트가 API에 전달됩니다.
- `jev-latest` API 실패·키 누락·지연 시 선택을 보류합니다. 다른 선택 알고리즘으로 자동 대체하지 않습니다.
- 깜빡임 직전 강조된 요소를 고정합니다. 자연스러운 짧은 깜빡임, 너무 긴 눈 감기, 프레임 단절, 얼굴 상실, 스크롤·DOM 변경 후에는 클릭을 취소합니다.
- 0.2.2에서는 눈 상태 추적과 CPU 시선 추론을 별도 스레드로 처리합니다. 눈꺼풀이 내려가기 시작하면 강조된 대상을 고정하고, 감는 동안 들어오는 시선 값과 Jev 선택 변경을 적용하지 않습니다. 눈을 감기 직전의 단발성 시선 튐에는 강조 표시를 최대 250ms 유지합니다. 눈을 뜬 개인별 기준을 학습하며, 감고 있는 표본으로 그 기준을 낮추지 않습니다.
- 패널의 **눈 뜸 / 눈 감는 중 / 양눈 감음** 표시로 제스처 인식 상태를 확인할 수 있습니다. 눈 감기는 감지되었지만 클릭 후보가 없으면 **선택된 대상 없음**을 표시합니다. 초록 테두리가 생긴 뒤 양눈을 완전히 0.6~2.0초 감았다 뜹니다. 긴 반쯤 감기는 클릭 대상으로 확정하지 않습니다.
- 클릭은 DOM의 `focus()`와 `click()`입니다. iframe, Shadow DOM 내부, canvas 내부 버튼, 파일 선택기·브라우저 UI·네이티브 입력이 필요한 기능은 지원하지 않습니다. 시스템 마우스 포인터를 이동하지 않습니다.
- 일반 웹페이지 최상위 문서에만 사용합니다. 스크롤·타이핑·드래그는 포함하지 않습니다. CPU가 느리면 시선 갱신이 느려지며 프레임 간격이 400ms를 넘으면 클릭 확정을 취소합니다.
- 로컬 서버는 `127.0.0.1:8765`에서만 수신하며 확장 origin과 연결 토큰을 검사합니다. 토큰은 `runtime.json`, 키는 `.env`에 저장하며 둘 다 Git에서 제외합니다.

## 점검

초기 버전에서 CPU 전용 PyTorch와 공식 가중치 로딩, 실제 웹캠 시선 출력, Chrome DOM 통합 동작을 확인했습니다. 모델만 측정한 평균 추론 시간은 스레드 2개에서 약 111ms였습니다. 이는 시선 정확도 측정이 아닙니다. 0.1.1은 얼굴 정규화와 보정 표본 수집을 수정하고 이에 대한 회귀 테스트를 추가했습니다.

0.2.0에서는 탭 전환·페이지 이동·이전 응답 차단, 9점 보정, 검색 제목 형태의 DOM 클릭을 자동 테스트합니다. Google 실제 검색 페이지는 테스트 환경의 자동 접속 차단으로 확인하지 못했으며, 여러 줄 제목과 중첩된 링크를 재현한 페이지에서 검증했습니다. 개인별 정밀도 개선은 실제 재보정 결과로 판단해야 합니다.

실제 Jev API 호출(USE_JEV 사용 시)과 사용자별 클릭 정확도는 사용자 보정 후 확인해야 합니다.

```powershell
node --test tests/core.test.cjs tests/worker.test.cjs
.venv/Scripts/python.exe -m unittest discover -s tests -p 'test_*.py' -v
.venv/Scripts/python.exe scripts/check_cpu.py
```

Linux에서는 `.venv/Scripts/python.exe` 대신 `.venv/bin/python`을 씁니다.

선택 사항: Playwright가 설치된 환경에서 `node tests/browser.cjs`로 실제 DOM에 가상 시선과 Jev 응답을 주입하는 통합 테스트를 실행합니다. `PLAYWRIGHT_PATH`와 `CHROME_PATH`로 실행 경로를 지정할 수 있습니다. 이 테스트는 실제 사용자 정확도나 Jev 품질을 측정하지 않습니다.

카메라가 열리지 않으면 Windows 카메라 권한(Linux는 `/dev/video*` 접근 권한, 보통 `video` 그룹), 다른 프로그램의 카메라 점유, `.env`의 `CAMERA_INDEX`를 확인합니다. API 키를 바꾸면 서버를 다시 시작합니다. CPU 스레드는 `.env`의 `CPU_THREADS`로 조절합니다. 비워 두면 자동으로 논리 코어 수의 절반(2~8개)을 씁니다. 이 노트북(논리 코어 16개)에서 얼굴 점 찾기와 함께 재 보니 int8 모델이 4개 57ms, 6개 46ms, 8개 41ms였고 12·16개는 서로 CPU를 다퉈 오히려 느렸습니다. 카메라가 여러 대면 서버 시작 때 터미널에 목록이 나오고 번호를 골라 쓸 수 있습니다(Enter는 `.env`의 `CAMERA_INDEX`). 확장을 시작하면 Chrome 창을 줄여 화면 양옆(6%)·아래(15%)에 여백을 두고, 중지하면 원래 크기로 되돌립니다. 여백 비율은 `extension/core.js`의 `MARGIN_SIDE`, `MARGIN_BOTTOM`에서 바꿉니다. Linux의 `start.sh`는 `SHRINK_WINDOW=0`으로 창 줄이기를 끕니다. Hyprland 같은 타일링 창 관리자는 창 크기를 직접 정해서, 확장이 창을 줄이면 타일 크기와 어긋나 화면이 깨지기 때문입니다. 팝업이 시작할 때 서버의 `/health`에서 이 값을 읽습니다(서버가 꺼져 있으면 줄입니다).

### 0.2.7 적용

가장자리 학습 범위를 화면 4~96%로 넓히고, 검증점 4개를 6~94%의 모서리 근처에 배치했습니다. 새 보정이 필요합니다. 눈 감김 기준을 개인별 눈 열림 대비 64%에서 70%로 조정하고, 클릭 허용 시간을 0.6~2.0초로 늘렸습니다. 패널에 눈 열림 비율을 표시합니다. 실제 사용자 인식률은 재확인이 필요하며, 적용하려면 서버도 재시작해야 합니다.

눈 상태만 도착하는 프레임에서는 보정 진행 표시를 유지합니다. 짧은 프레임 지연이나 얼굴 추적 손실로 표본을 즉시 0으로 초기화하지 않습니다. 복귀 후 안정화 시간을 적용하고 10초보다 오래된 표본은 다음 시선 결과 수신 시 제외합니다. 점 이동이나 15초 수집 실패에 따른 재시도 때는 새로 수집합니다.

보정은 점이 안정될 때까지 기다리지 않고 점마다 정해진 시간(0.6초 대기 + 1초 수집)만 표본을 모읍니다. 오래 기다리면 그사이 머리가 움직여 오히려 부정확해지기 때문입니다. 눈을 옮기는 중이던 튀는 값은 중앙값에서 먼 값을 버리는 방식으로 뺍니다.

눈 감기 클릭은 마지막으로 선택되어 초록 테두리로 표시된 대상을 사용합니다. 시선 이동, 선택 후 시간 경과, Jev 선택 보류로는 선택을 지우지 않으며, 새 대상이 선택되면 교체합니다. 클릭 완료, 탭 전환, 스크롤, 얼굴 추적 끊김, 대상 변경 시에는 선택을 초기화합니다.

교차검증 오차가 화면 비율 0.15를 넘으면 오차를 보여 주고 **그래도 사용** 또는 **다시 보정**을 고르게 합니다. 보정에 실패하면 보정 화면에 **다시 보정** 버튼이 나옵니다.

실행 중인 서버를 `Ctrl+C`로 종료하고 `./start.ps1`로 다시 실행합니다. Chrome 확장 관리에서 확장의 새로고침 버튼을 누른 뒤 **사용할 웹페이지도 새로고침**하고 다시 보정합니다. Chrome에서 새 사이트 접근 권한 확인이 표시되면 허용하고, 확장 세부정보의 사이트 액세스를 **모든 사이트에서**로 설정합니다. 이전 탭에 주입된 구버전 스크립트는 확장만 새로고침해도 남을 수 있습니다.

0.2.1은 페이지 메시지 전달 실패 시 로딩 완료 이벤트 없이도 자동으로 재연결합니다. 일시적인 로컬 서버 연결 끊김도 실행 세션의 보정값을 유지하고 재시도합니다. 잘못된 연결 토큰이나 복구 불가 서버 오류는 원인을 표시하고 중지합니다. 보정 실패 시에는 카메라 세션과 오류 화면을 유지하므로 **다시 보정**을 누를 수 있습니다. ESC 또는 중지 버튼은 자동 재연결까지 취소합니다.

보정 실패는 머리 움직임만을 뜻하지 않습니다. 최신 버전에서도 오차가 크다면 화면에 표시된 `보정 점과 시선 출력의 대응 오차`, `검증 … 오차 …px`, `안정된 시선 표본 부족` 중 어느 단계인지 확인합니다. 카메라 내부 파라미터 추정, 얼굴 형태 차이, 모델의 개인별 시선 오차는 여전히 실제 보정으로 확인해야 합니다.
