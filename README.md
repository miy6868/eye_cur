# 시선 클릭: 시선으로 웹페이지 누르기 (CPU 전용)

웹캠으로 시선을 읽어 Chrome 웹페이지의 버튼·링크를 고르고, 입을 벌렸다 다물면 클릭합니다.

```
웹캠 → MediaPipe 얼굴 점 → 얼굴 정규화 → UniGaze-B(ONNX Runtime, CPU) → 시선 각도
     → 로컬 서버(WebSocket) → Chrome 확장 → 9점 보정 회귀 → 화면 좌표 → 떨림 필터
     → 가까운 요소 선택(NearestSelector) → 입 벌리기 클릭
```

- Windows 또는 Linux + Chrome, 모니터 한 대에서 쓰는 개인·연구용 시제품입니다.
- 시선 모델은 [UniGaze-B](https://github.com/ut-vision/UniGaze)(ViT-B/16, 약 8600만 파라미터, `unigaze_b16_joint` 가중치)입니다. 설치할 때 공식 가중치를 ONNX로 바꾸고, 실행 중에는 ONNX Runtime으로 CPU에서만 돌립니다. CUDA는 쓰지 않습니다.
- 시스템 마우스 포인터는 움직이지 않습니다. 클릭은 페이지 요소에 실제 마우스와 같은 순서의 이벤트(pointerdown·mousedown → `focus()` → pointerup·mouseup → `click()`)를 보내는 것입니다.
- 파일별 역할, 메시지 형식, 조정 값 위치는 `CLAUDE.md`에 있습니다.

## 설치

### Windows (시연 PC)
1. 프로젝트 폴더를 `C:\eye_cur`처럼 **영어로만 된 경로**에 둡니다. 한글 폴더, 한글 사용자 이름, OneDrive `바탕 화면` 아래에서는 MediaPipe가 모델 파일을 열지 못합니다. 폴더를 옮겼다면 setup을 다시 실행합니다.
2. [uv](https://docs.astral.sh/uv/getting-started/installation/)를 설치합니다.
3. 그 폴더에서 일반 PowerShell 창(ISE나 우클릭 실행이 아닌 창)을 열고 실행합니다.
   ```powershell
   powershell -ExecutionPolicy Bypass -File .\setup.ps1
   ```
   Python 3.11 가상환경, CPU용 torch, 라이브러리 설치, 가중치 다운로드(약 346MB), ONNX 변환(fp32, int8)까지 합니다. 마지막 모델 점검에서 `PASS`가 나와야 끝입니다. `DLL load failed`가 나오면 [VC++ 재배포 패키지](https://aka.ms/vs/17/release/vc_redist.x64.exe)를 설치합니다(Windows N/KN 에디션은 미디어 기능 팩도 필요합니다).

### Linux (Arch 등)
Arch 기본 Python 3.13에는 `mediapipe 0.10.21` 휠이 없어서 `setup.sh`가 uv로 Python 3.11을 따로 받습니다(`sudo pacman -S uv`).
```bash
./setup.sh
.venv/bin/python scripts/check_camera.py   # 선택: 카메라·얼굴·시선 출력 확인
```
카메라는 Windows에서 DirectShow, Linux에서 V4L2로 엽니다.

### Chrome 확장
`chrome://extensions` → 개발자 모드 → **압축해제된 확장 프로그램을 로드합니다** → `extension` 폴더를 고릅니다. 사이트 액세스는 **모든 사이트에서**로 둡니다.

## 사용
1. 서버 실행: Windows `powershell -ExecutionPolicy Bypass -File .\start.ps1`, Linux `./start.sh`.
   - 카메라가 여러 대면 번호를 묻습니다(Enter = `config.toml`의 `camera_index`).
   - 콘솔에 나오는 **연결 토큰**을 복사합니다(`runtime.json`에도 있습니다). Windows 10 콘솔에서 글자를 선택한 채로 두면 서버가 멈추므로, 복사한 뒤 `Esc`를 누릅니다.
2. `http://127.0.0.1:8765/demo`(시험용 페이지)나 아무 일반 웹페이지를 엽니다.
3. 확장 아이콘 → 토큰 입력 → **시작**.
4. 보정(저장된 보정이 없을 때): 머리를 고정하고, 밝은 화면에 나오는 초록 점을 봅니다.
   - 3×3 점(화면 가장자리에서 10%)을 ㄹ자로 한 번, 거꾸로 한 번 봅니다. 모두 18번, 약 30초입니다.
   - 보정을 켜면 첫 점이 바로 한 번 크게 나타나 작아집니다(서버·모델이 아직 준비 중이어도). 그 뒤 최소 0.5초를 더 기다렸다가 첫 점을 시작하므로 화면을 찾아 눈을 옮길 시간이 있습니다.
   - 다음 점 자리는 회색 점선 원으로 미리 보입니다. 점이 크게 나타나 0.8초 동안 작아지는 동안은 표본을 버리고, 그 뒤 0.8초 동안 모읍니다.
   - 끝나면 "점 오차"(교차검증 오차, px)가 나옵니다. 기준(화면 비율 0.15)보다 크면 **그래도 사용** 또는 **다시 보정**을 고릅니다.
5. 버튼을 바라봅니다. 0.3초 이상 보면 초록 테두리가 생깁니다. **입을 0.5~2.0초 벌렸다 다물면** 다무는 순간 한 번 클릭합니다(시간은 기본값이고 `config.toml`에서 바꿉니다). 입을 벌리는 동안 테두리는 주황색입니다.
   - 입을 벌리는 동안 커서 자리에 고리가 시계 방향으로 차오릅니다(2초에 가득). 색과 아래 글자가 "지금 다물면 무엇이 되는지"입니다: 회색 `…` = 너무 짧아 아무 일 없음(0.5초 전), 초록 `클릭`, 빨강 `대상 없음`, 보라 `메뉴`(2초 넘음, 메뉴가 떠 있으면 `메뉴 닫기`). 세지 않고 색이 바뀔 때 다물면 됩니다.
6. **입을 2초 넘게 벌렸다 다물면 메뉴**가 열립니다(눈 클릭 모드는 2초 넘게 감았다 뜨기). 메뉴 버튼도 똑같이 바라보고 입을 벌렸다 다물어 누릅니다. 메뉴에서 같은 동작을 한 번 더 하거나 **닫기**를 누르면 닫힙니다.
   - **뒤로 / 앞으로 / 새로고침**
   - **스크롤**: 화면 위·아래 25% 띠를 보고 있으면 그쪽으로 스크롤합니다. 화면 끝에 가까울수록 빠르고, 가운데를 보면 멈춥니다. 입을 벌렸다 다물면 끝납니다. 시선 아래의 스크롤 상자(디스코드 대화 목록, 네이버 블로그 본문 iframe 등)를 먼저 움직이고, 없으면 페이지 전체를 움직입니다.
   - **탭**: 이 창의 웹페이지 탭이 큰 카드로 나옵니다(한 화면 8개, 이전/다음). 고르면 그 탭으로 가고 보정은 그대로 이어집니다. `chrome://` 탭은 가면 돌아올 수 없어서 목록에서 뺍니다.
   - **키보드**: 화면 75%를 차지하는 큰 일반 자판(두벌식/QWERTY)입니다. 시선은 위아래가 좌우보다 덜 정확해서 키를 세로로 길게 만들었습니다. 한/영, Shift(한 글자만), 123(숫자·기호), 스페이스, 지우기, 엔터, 닫기, 모두 삭제(맨 아래 오른쪽)가 있습니다.
     - 맨 위 줄에 입력칸 내용 끝부분이 보입니다. 입력칸이 화면 아래쪽이면 키보드가 위로 갑니다.
     - 그 아래 줄은 추천 단어 5개입니다. 친 글자로 시작하는 단어부터, 자주 쓰는 순서로 나옵니다. 고르면 단어와 띄어쓰기가 들어갑니다.
     - 지우기는 조합 중이면 자모 하나만, 아니면 글자 하나를 지웁니다. 엔터는 사이트가 처리하면(메시지 보내기 등) 그대로, 아니면 검색칸은 제출, 여러 줄 칸은 줄바꿈입니다.
     - 키보드 밖 페이지 요소(입력칸, 사이트의 자동완성 목록)도 그대로 바라보고 누를 수 있습니다.
     - 입력칸을 누르면 키보드가 저절로 뜹니다(팝업 스위치로 끌 수 있음). 구글 검색칸처럼 페이지가 열릴 때 이미 초점이 들어가 있는 칸도 시선으로 누르면 뜹니다.
7. 끝낼 때는 확장 아이콘의 **중지**를 누릅니다.

팝업에는 실행 상태, 마지막 보정의 점 오차, **다시 보정**, **중지**, **화면에 정보 표시**와 **입력칸을 누르면 키보드 표시**(기본 켜짐, 끄면 메뉴로만 엶) 스위치가 있습니다.
- 정보 표시를 끄면(기본) 화면에는 파란 커서, 빨간 원본 점, 초록 테두리만 보이고 사이트의 키 입력을 가로채지 않습니다.
- 켜면 왼쪽 아래에 정보 상자(눈·입 상태와 MAR, 머리 기울기·거리, 떨림, 상태 문구, 그래프)가 보이고, 단축키 `F`(떨림 필터 바꾸기)와 `ESC`(중지)가 동작합니다. 정보 상자는 마우스가 통과합니다.
- 보정 중에는 정보 표시 설정과 상관없이 안내가 보입니다.

보정은 확장 저장소에 남아서 탭을 바꾸거나, 페이지를 이동하거나, 브라우저를 다시 켜도 이어집니다. 창 크기·위치·화면 배율이 바뀌면 저장된 보정을 버리고 다시 보정합니다. Chrome 설정·새 탭처럼 확장이 들어갈 수 없는 페이지나 다른 앱에 있을 때는 멈췄다가, 일반 웹페이지로 돌아오면 다시 이어 갑니다.

코드를 바꾼 뒤에는 서버를 `Ctrl+C`로 끄고 다시 실행합니다. 확장 관리에서 확장을 새로고침한 다음 **사용할 웹페이지도 새로고침**합니다. 이미 열려 있던 탭에는 옛 스크립트가 남아 있기 때문입니다.

## 설정
`config.toml`(저장소에 들어 있습니다. 비밀값이 없어서 그대로 고쳐 쓰면 됩니다. 바꾼 뒤에는 서버를 다시 시작합니다):

| 키 | 뜻 |
|---|---|
| `camera_index` | 기본 카메라 번호(기본 0) |
| `cpu_threads` | 시선 모델 스레드 수. 0(기본)이면 논리 코어 수의 절반(2~8개) |
| `gaze_int8` | `true`(기본) = int8 모델, `false` = fp32 모델 |
| `camera_intrinsics` | 측정한 카메라 내부 파라미터 JSON 파일 경로(`camera_matrix`, `dist_coefficients`). 비우면 추정값 |

그 아래 칸에는 인식·동작 값이 있습니다. 각 값의 뜻은 파일 안 주석에 있고, 바꾼 뒤에는 서버를 다시 켜고 쓰던 웹페이지도 새로고침합니다.

| 칸 | 값 |
|---|---|
| `[mouth]` | 입 벌림/다뭄 문턱값(MAR) |
| `[eyes]` | 눈 감는 중/감음/다시 뜸 문턱값 |
| `[click]` | 클릭 방식(`"mouth"` 입, `"eyes"` 양눈 감기), 클릭으로 인정하는 최소·최대 시간(최대를 넘으면 메뉴), 연속 클릭 방지 시간 |
| `[select]` | 대상을 몇 ms 보면 선택할지, 선택을 바꾸는 거리 여유 |
| `[calibration]` | 보정 첫 점 대기, 점마다 눈 옮기는 시간·모으는 시간·최소 표본·최대 시간, 통과 기준 오차 |
| `[scroll]` | 스크롤 띠 크기, 최저·최고 속도 |
| `[keyboard]` | 가상 키보드 높이(화면 %) |

코드 안 스위치(`extension/content.js` 위쪽):
- `CLICK_DRIFT`(기본 `false`): `true`면 클릭할 때마다 그 요소를 보고 있었다고 보고 시선 오프셋을 절반만큼 고칩니다.

그 밖의 값(필터, 후보 반경, 메뉴 글자 크기 등)의 위치는 `CLAUDE.md`의 "조정 값 위치" 표에 있습니다.

## 설계 결정과 측정 기록
다시 시도하지 않도록 남겨 둔 이유와 수치입니다.

**시선 모델**
- 예전 모델 GazeTR-Hybrid는 git 기록에 남아 있습니다. `vendor/unigaze.py`는 공식 코드(timm 0.3.2가 필요한데 지금 torch와 맞지 않음)와 같은 계산을 torch만으로 다시 쓴 것입니다. 공식 코드와 출력 차이는 3×10⁻⁷ 이하입니다.
- 속도(Ryzen 7 5825U, 얼굴 한 장, 스레드 4개): GazeTR 27ms, UniGaze torch 170ms, ONNX fp32 104ms, **ONNX int8 57ms(기본)**. 스레드를 6개로 하면 46ms, 8개면 41ms이고, 12·16개는 CPU를 서로 다퉈 오히려 느렸습니다.
- int8은 fp32와 출력이 최대 0.035rad(약 2°) 다르고 흔들림이 20~50% 큽니다. 실제로 써 보니 흔들림이 크게 느껴지지 않았고 속도가 더 중요해서 기본으로 씁니다. 고정된 차이는 보정이 흡수합니다. fp16은 일반 CPU에서 빨라지지 않습니다.
- 추론은 이전 추론이 끝나야 다음 프레임을 받으므로 2~3프레임에 한 번 돕니다. 그 사이는 응시 고정 필터가 메웁니다. 눈 상태(감김·입)는 추론과 별도로 모든 프레임에서 계산합니다.

**얼굴 정규화**
- ETH-XGaze 3D 얼굴 템플릿의 눈꼬리 4점과 코 양옆 2점으로 머리 자세를 구하고, 얼굴을 224×224(초점 960, 거리 600)로 정규화합니다. UniGaze 공식 코드처럼 RGB로 바꾸고 0~1로 나눈 뒤 ImageNet 평균·표준편차로 정규화합니다.
- UniGaze 출력은 [pitch, yaw]인데, 확장에는 [yaw, pitch](좌우, 위아래)로 바꿔 보냅니다. 같은 얼굴을 좌우로 뒤집으면 yaw만 부호가 바뀌는 것으로 순서를 확인했습니다.
- 카메라 내부 파라미터는 추정값입니다(초점거리 = 영상 긴 변). 화면 보정이 이것을 대신하지는 않습니다. 패널의 거리 값은 절대값보다 변화율을 보는 용도입니다.

**보정**
- 움직이는 점을 따라 보는 방식에서 고정 점 응시로 바꾼 이유(기록 4개): ① 따라 보는 눈은 점보다 늦고 덜 움직여서, 버튼을 응시할 때와 값이 달랐습니다(한 기록은 4점 모두 왼쪽 위로 65~150px 빗나감). ② 시선 지연 추정이 4번 중 3번 상한(300ms)에 걸렸습니다. ③ 어두운 보정 화면과 밝은 웹페이지 사이에 조명·동공 크기가 달라 시선 값이 통째로 밀렸습니다. 그래서 지금은 밝은 화면에서 보정합니다.
- 왕복 순서: 점마다 두 번 본 차례의 평균이 같아서(8.5번째), 천천히 밀리는 시선 값이 모든 점에 똑같이 더해지고 회귀의 상수항이 흡수합니다. 점마다 바퀴별 중앙값을 구해 두 바퀴를 평균하고, 표본 9개로 회귀합니다.
- 0.8초를 기다리는 이유: 눈꺼풀은 눈보다 늦게 내려옵니다. 기록 2개에서 아래쪽 점은 0.5초가 지나도 값이 계속 바뀌었고, 0.8~1초 뒤 값만 쓰자 아래 줄 오차가 줄었습니다(88→57px, 106→80px). 눈을 감아 표본이 3개보다 적으면 점 하나에 최대 2.1초까지 기다립니다.
- 회귀는 입력마다 평균 0, 표준편차 1로 맞춘 1차 회귀입니다. 2차는 계수가 많아서 9점으로는 과적합합니다(16점 이상일 때만 교차검증으로 2차를 고려합니다). "점 오차"는 점 하나씩 빼고 맞혀 보는 교차검증 오차입니다.
- 입력은 시선 각도 2개뿐입니다. 홍채 위치를 더한 4개 입력은 예전 기록 4개 모두에서 더 나빴습니다(85/117/86/65px vs 113/174/101/74px).
- 눈을 크게/가늘게 뜬 정도를 계산으로 빼는 보정도 시도했지만 더 나빠져서 뺐습니다. 대신 보정 때 눈 열림 범위(5~95%)를 0.05 넘게 벗어나면 패널에 노란 경고를 띄웁니다.
- 머리 기울기·끄덕임·거리를 보정 때와 비교해 패널에 표시합니다. 정규화가 이 변화를 시선 값에서 다 지우지 못해서, 오차와의 관계를 보기 위한 측정용입니다.
- 보정할 때마다 표본(시선 값, 촬영 시각, 점 번호, 차례, 머리 상태, 홍채, 눈 열림)과 점별 중앙값이 서버의 `logs/pursuit.jsonl`에 한 줄씩 저장됩니다. 카메라 이미지는 저장하지 않습니다. 회귀나 입력을 바꿀 때 같은 자료로 비교하는 데 씁니다.

**눈·입 판정**
- 입 MAR 문턱값은 벌림 0.20, 다뭄 0.12입니다. 처음 0.30/0.20은 입을 꽤 크게 벌려야 했습니다. 말할 때 짧게 벌어지는 입은 0.5초 최소 시간으로 거릅니다.
- 눈은 개인별 뜬 눈 기준(최근 값의 80분위) 대비 비율로 판정합니다. 두 눈이 모두 0.60 아래면 '감는 중'(이때 시선 값을 쓰지 않음), 0.50 아래면 '감음', 0.62 위면 다시 뜬 것입니다. 처음 0.78/0.70/0.80은 아래쪽을 볼 때 눈꺼풀이 내려와(0.66~0.8) 시선이 자주 멈춰서 낮췄습니다. 감는 중이나 얼굴을 놓친 뒤 250ms 동안은 시선 결과를 버립니다.

**대상 선택과 클릭**
- 기본 NearestSelector: 시선 주변 후보(반경 100~240px) 중 가장 가까운 요소가 0.3초 동안 계속 1등이면 고릅니다. 이미 고른 요소가 있으면 새 1등이 30px 이상 더 가까울 때만 바꿉니다. 서버로 아무것도 보내지 않습니다.
- 검색 결과 제목 같은 링크는 제목 텍스트의 실제 줄 영역을 후보로 삼고 상위 링크를 클릭합니다. 가려진 요소, 클릭 직전에 위치나 목적지가 바뀐 요소는 클릭하지 않습니다.
- 다른 주소의 iframe 속 요소(예: 네이버 지도 검색 결과·장소 상세)도 후보가 됩니다. 모든 프레임에 `frame.js`가 들어가 자기 후보를 모아 주고 클릭을 대신합니다.
- 클릭 대상은 입을 벌리기(또는 눈을 감기) 시작하는 순간 고정됩니다. 스크롤, 탭 전환, 창 초점 잃음, 얼굴 놓침, 프레임 간격 400ms 초과는 클릭을 취소합니다. 2초가 넘는 동작은 클릭 대신 메뉴를 엽니다.

## 제한
- 일반 웹페이지 최상위 문서와 그 바로 안의 iframe만 됩니다. iframe 속 iframe, CSS로 돌리거나 키운 iframe, Shadow DOM 안쪽, canvas 안의 버튼, 파일 선택기, 브라우저 UI는 안 됩니다. 드래그는 없습니다.
- 스크롤 모드는 같은 주소의 iframe 안(네이버 블로그·카페 본문)은 스크롤하지만, 다른 주소의 iframe 안(네이버 지도 목록 등)은 스크롤하지 못합니다. 가상 키보드는 맨 위 문서의 입력칸에만 쓰고, iframe·Shadow DOM 속 입력칸에는 못 씁니다.
- 탭 닫기는 실수로 누르면 되돌리기 어려워 메뉴에 넣지 않았습니다.
- 정확도는 사람과 카메라에 따라 달라서 실제 보정으로 확인해야 합니다.
- 로컬 서버는 `127.0.0.1:8765`에서만 받고, 확장 origin과 연결 토큰을 검사합니다. 토큰(`runtime.json`)은 git에서 제외합니다. 외부 API로는 아무것도 보내지 않습니다.
