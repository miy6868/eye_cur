# 시연 게임 (`demo/`)

사람들이 시선 추적을 재미있게 써 보도록 만든 게임. 2026-11 사용자 승인으로 3개(유령 쫓기, 운석 피하기, 두더지 잡기)만 만들었다.
제안했지만 보류한 것: 손전등 보물찾기, 풍선 터뜨리기(응시), 카드 짝 맞추기.

## 시선의 약점에 맞춘 규칙
시선은 수십~수백 px 오차·떨림이 있고, 입 클릭은 벌리기 시작부터 다물기까지 1초 남짓 걸린다(그 사이 시선 값도 멈춘다).
- 정밀 조종이 필요 없게: 시선 게임 두 개는 클릭 없이 좌표만 쓰고, 판정을 그림보다 넓게(유령) 또는 좁게(우주선 부딪힘) 잡아 오차가 사용자 편이 되게 한다.
- 떨림: 우주선은 시선 x를 지수적으로 늦게 따라가고 y는 좁은 폭만 움직인다(사용자 요청: 좌우만, 어색하지 않을 만큼만 위아래). 확장의 떨림 필터 결과를 한 번 더 부드럽게 하는 셈.
- 유령 쫓기: 집만 바라보고 버티지 못하게 울타리 반지름을 "유령 반지름 + 시선 여유"보다 크게 둔다.
- 두더지: 확장의 대상 선택 + 입 클릭을 그대로 쓴다(구멍 = 큰 버튼). 두더지가 숨은 직후에도 잠깐은 잡은 것으로 치고, 그동안 다음 두더지를 내지 않는다.
- 운석·유령은 사용자 요청대로 끝없이 어려워져 결국 끝나게 한다.

## 시선 좌표 전달
페이지는 원래 시선 위치를 모른다(커서·선택은 content.js 닫힌 shadow DOM 안). 게임을 위해 content.js가 `/demo` 페이지에만 `postMessage`로 좌표를 보낸다.
다른 사이트로 넓히면 아무 페이지나 시선 위치를 읽을 수 있어 막아 두었다(사용자 선택).

## 시선이 게임에 안 먹던 문제 (2026-11-03)
사용자 보고: 유령 쫓기·운석 피하기에 시선이 영향을 안 줌. 헤드리스 Chromium에서 isolated world → 페이지 `postMessage`는 정상 도착했고, 가만히 둔 마우스가 가짜 mousemove를 내지도 않았다.
실제 원인은 확인하지 못했고 후보를 모두 막았다: 시선이 1초 안에 왔으면 마우스 무시, `localhost:8765`도 허용, `/demo` 응답에 `Cache-Control: no-cache`(시험 중 Chrome이 고치기 전 gaze.js를 캐시로 썼다), 위쪽 띠에 조종 출처 표시(⚠ 시선 신호 없음 = 대개 확장 새로고침 안 함).

## 디자인 다시 만들기 (2026-11-03)
사용자 평: 첫 버전(이모지·단색 도형)은 "조잡하다, 현대적이고 진짜 같게". 사용자 선택: 시네마틱 그림체, 효과음 + 끄기 버튼(배경음 없음).
- 이미지 파일 없이 캔버스·SVG로 그린다(학교 PC 인터넷 여부와 무관). 배경(성운·숲·들판), 운석, 빛 번짐, 가장자리 어둡게는 크기가 바뀔 때만 미리 그려 두고 프레임마다 drawImage만 한다. 학교 노트북은 시선 모델이 CPU를 많이 써서 블러·그림자 효과와 backdrop-filter는 게임 화면에서 쓰지 않고, 캔버스 배율은 devicePixelRatio 1.5까지만.
- 측정: 개발 PC 헤드리스 Chromium 1600×900에서 세 게임 모두 약 60fps(시선 모델 없이). 학교 PC에서는 아직 못 쟀다.
- 효과음은 Web Audio로 합성. Chrome은 실제(isTrusted) 입력이 있어야 AudioContext를 켜 주고, 확장의 시선 클릭(GazeDOM.press가 만든 이벤트)은 해당되지 않는다. 그래서 소리 버튼이 "마우스로 한 번 누르세요" 상태를 보여 준다.
- 시선 게임은 시선 신호가 0.8초 넘게 끊기면(얼굴 잃음·입 벌림) 멈춘다(`gazeLost`). 마우스로 할 때는 멈추지 않는다. 조종 출처 표시는 입 클릭(1초 남짓) 동안 깜빡이지 않게 3초 기준.
- 시선 오차 대책 추가: 연료는 가까이 가면 끌려온다, 운석을 스치면 보너스(정밀함에 벌 대신 상), 시작 직후 보호막, 넷 중 하나의 운석은 우주선 쪽으로 와서 한 자리에 가만히 있으면 못 버틴다. 두더지는 그림 위에 투명 버튼을 겹쳐 확장의 대상 선택이 그대로 잡는다(dom.js는 투명도를 거르지 않는다).

## AI 티 나는 디자인 걷어내기 (2026-11-03)
사용자 평: 위 디자인은 "전형적인 AI slop". 기준은 https://impeccable.style/slop/ (수준 높일 필요 없이 slop만 아니면 됨).
걸렸던 것과 바꾼 것:
- 보라·청록 팔레트, 배경 방사형 빛 번짐, 제목 그라데이션 글자, 빛나는 테두리 → 테스트 페이지와 같은 밝은 회색 바탕·흰 상자, 강조색 하나(초록).
- 제목 위 영어 작은 라벨(DEEP SPACE RUN 등), 칩·배지, 아주 둥근 모서리, 얇은 테두리 + 넓은 그림자, 카드 위로 뜨는 효과 → 모두 뺐다.
- 대충 그린 SVG 마스코트·장식 격자선, 똑같은 카드 세 장 → 게임 목록은 큰 줄 세 개에 실제 게임 화면 캡처(`demo/img`).
- 큰 숫자 + 통계 칩 결과 화면, 깜빡이는 NEW RECORD 배지, 튕기는 글자 → 점수 한 줄과 문장 요약.
- 게임 장면 안의 빛·입자(캔버스)는 게임 그림이라 그대로 두었다.
썸네일 다시 만들기: 헤드리스 Chromium(CDP)으로 게임을 시작하고 `.hud,.screen,.banner`를 숨긴 뒤 `Page.captureScreenshot`(jpeg, 0.56배)으로 찍었다.

## 두더지 판정 조이기, 게임 목록 가로 배치 (2026-11-03)
사용자: 두더지 판정이 너무 후하다. 바꾼 것: 숨은 뒤 봐주는 시간 0.8 → 0.3초, 나와 있는 시간 3→1.8초 → 2.4→1.5초, 빈 구멍을 누르면 50점 깎고 연속 끊기(전에는 벌점 없어 마우스로 마구 눌러도 손해가 없었다), 구멍 버튼을 둔덕 전체(구멍 폭 2.7배)에서 구멍과 두더지 몸 정도(2.2배)로 줄임.
게임 목록은 세로 줄 세 개 → 가로 칸 세 개(사용자: 가로가 시선으로 고르기 쉽다).
