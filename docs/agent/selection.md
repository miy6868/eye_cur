# 대상 선택과 클릭

## 선택
- `NearestSelector`: 시선 주변 후보 중 가장 가까운 요소가 `dwell_ms` 동안 계속 1등이면 고른다. 이미 고른 요소가 있으면 새 1등이 `switch_margin_px` 이상 더 가까울 때만 바꾼다. 서버·외부로 아무것도 보내지 않는다(예전 Jev API 연동은 삭제).
- 후보 반경은 보정 오차에 따라 커진다(`content.js` `candidates()`).

## 후보
- 링크·버튼·입력칸·`summary`·`label`·`[onclick]`, 메뉴 항목·탭·선택지 같은 `role`, 그리고 시선 주변에서 `cursor: pointer`가 되는 요소(선택자에 안 걸리는 JS 전용 버튼).
- 블록 모양 링크·버튼(카드, 메뉴 항목, 목차 줄)은 상자 전체, 여러 줄로 나뉜 글 속 링크는 실제 글자 줄을 영역으로 쓴다. 링크를 글자 줄로만 재면 카드·목차가 빠졌다.
- 가려진 요소, 클릭 직전에 위치나 목적지가 바뀐 요소는 클릭하지 않는다. 투명하지만 맨 위에 있어 마우스가 누르게 되는 요소(위키백과 메뉴 버튼)는 후보다.
- 다른 주소의 iframe 속 요소(네이버 지도 검색 결과·장소 상세)도 후보. 모든 프레임에 `frame.js`가 들어가 자기 후보를 모으고 클릭을 대신한다.

## 클릭
- 시스템 마우스는 움직이지 않는다. 실제 마우스와 같은 순서로 이벤트를 보낸다: pointerdown·mousedown → `focus()` → pointerup·mouseup → `click()`.
- 클릭 대상은 입을 벌리기(눈 감기) 시작하는 순간 고정된다.
- 스크롤, 탭 전환, 창 초점 잃음, 얼굴 놓침, 프레임 간격이 크게 벌어지면 클릭을 취소한다.
- 탭 닫기는 실수로 누르면 되돌리기 어려워 메뉴에 넣지 않았다.
- `CLICK_DRIFT`(content.js 위쪽, 기본 꺼짐): 켜면 클릭할 때마다 그 요소를 보고 있었다고 보고 시선 오프셋을 조금 고친다.

## 스크롤
- 시선 아래의 스크롤 상자(디스코드 대화 목록, 네이버 블로그 본문 iframe)를 먼저 움직이고, 없으면 페이지 전체. 다른 주소 iframe 안은 스크롤하지 못한다.
