# 시선 모델

## 모델
- UniGaze-B(ViT-B/16, 약 8600만 파라미터, `unigaze_b16_joint` 가중치). 설치 때 공식 가중치를 ONNX(fp32, int8)로 바꾸고 실행 중에는 ONNX Runtime으로 CPU에서만 돌린다. CUDA는 쓰지 않는다(학교 PC).
- 예전 모델 GazeTR-Hybrid는 git 기록에 남아 있다.
- `vendor/unigaze.py`는 공식 코드(timm 0.3.2가 필요한데 지금 torch와 맞지 않음)와 같은 계산을 torch만으로 다시 쓴 것. 공식 코드와 출력 차이는 3×10⁻⁷ 이하.

## 속도 (Ryzen 7 5825U, 얼굴 한 장)
| 방식 | 스레드 4개 |
|---|---|
| GazeTR | 27ms |
| UniGaze torch | 170ms |
| ONNX fp32 | 104ms |
| ONNX int8 | 57ms |

- int8은 스레드 6개 46ms, 8개 41ms. 12·16개는 CPU를 서로 다퉈 오히려 느렸다.
- int8은 fp32와 출력이 최대 0.035rad(약 2°) 다르고 흔들림이 20~50% 크다. 실제로 써 보니 흔들림이 크게 느껴지지 않았고 속도가 더 중요해서 기본으로 쓴다. 고정된 차이는 보정이 흡수한다.
- fp16은 일반 CPU에서 빨라지지 않는다.

## 프레임 흐름
- 추론은 이전 추론이 끝나야 다음 프레임을 받으므로 몇 프레임에 한 번 돈다. 그 사이는 응시 고정 필터가 메운다. 눈·입 상태는 추론과 별도로 모든 프레임에서 계산한다.
- 무거운 페이지에서도 프레임이 밀리지 않는다: 워커는 페이지가 앞 프레임을 다 처리할 때까지 기다리고, 그 사이 온 프레임은 최신 하나만 보낸다(몇 초 전 시선이 쌓였던 문제).

## 얼굴 정규화
- ETH-XGaze 3D 얼굴 템플릿의 눈꼬리 4점과 코 양옆 2점으로 머리 자세를 구하고, 얼굴을 224×224로 정규화한다. UniGaze 공식 코드처럼 RGB로 바꾸고 0~1로 나눈 뒤 ImageNet 평균·표준편차로 정규화한다.
- UniGaze 출력은 [pitch, yaw]인데 확장에는 [yaw, pitch]로 바꿔 보낸다. 같은 얼굴을 좌우로 뒤집으면 yaw만 부호가 바뀌는 것으로 순서를 확인했다.
- 카메라 크기(2026-11-01, 개발 노트북 내장 웹캠, 같은 자리): 640×480 → 1280×720으로 올리면 두 눈 바깥 꼬리 사이가 89px → 130px(약 1.5배; 이 카메라는 16:9가 세로 시야는 같고 좌우로 넓다). FaceMesh 1장 4.0 → 5.9ms, 둘 다 30fps. 1280×720 YUYV는 10fps뿐이라 MJPG를 요청한다. 얼굴이 작을수록 정규화 때 확대가 커져 흐려지므로 멀리 앉을 때를 위해 올렸다. 멀리 앉은 상태의 정확도는 아직 재지 않았다.
- 학교 노트북(2026-11-01, Windows DSHOW, 같은 자리): 예전 코드처럼 MJPG를 크기보다 먼저 요청하면 DSHOW가 크기를 바꾸며 YUY2로 되돌려 HD WebCam 2MP가 1280×720 10fps, 1920×1080 5fps였다. 크기 뒤에 다시 요청하니 둘 다 MJPG 30fps. 두 눈 바깥 꼬리 사이 151px(1280×720) → 228px(1920×1080), 홍채 지름 20 → 31px, FaceMesh 6.4 → 8.1ms. 1080p FHD Camera(광각, 통 모양 왜곡 큼)는 어느 크기나 22fps이고, 초점거리 추정(긴 변)이 광각에 맞지 않아 쓰지 않는 쪽을 권한다. EShare Virtual Camera는 가상 카메라라 쓰지 않는다.
- 여러 사람(2026-11-01): `max_num_faces=1`이면 MediaPipe가 먼저 찾은 얼굴 하나를 잡아, 사용자 얼굴을 잠깐 놓친 뒤 뒷사람으로 넘어갈 수 있었다. 얼굴을 여러 개 찾고 직접 짠 규칙(`FaceLock`)으로 고른다: 처음엔 두 눈 꼬리 사이가 가장 긴 얼굴, 이후엔 바로 전 자리에서 얼굴 크기만큼 안에 있는 얼굴, 다른 얼굴이 정해진 배수 넘게 크면 그쪽으로, 사용자보다 정해진 비율보다 작은 얼굴은 잊기 시간 전까지 무시. 크기 기억은 매 프레임 갱신해 천천히 뒤로 물러나는 사용자는 계속 따라간다. 학교 노트북 1280×720, 얼굴 1명: FaceMesh 1개 5.0ms → 3·5개 7.0ms(1명뿐이면 얼굴 찾기를 매 프레임 다시 돌려서). 실제 여러 사람 앞에서는 아직 재지 않았다.
- 카메라 내부 파라미터는 추정값(초점거리 = 영상 긴 변). 화면 보정이 이것을 대신하지는 않는다. 패널의 거리 값은 절대값보다 변화율을 보는 용도.
